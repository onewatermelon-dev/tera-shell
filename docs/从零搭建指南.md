## 1. 环境准备

1. **Node.js** ≥ 20（Vite 8 要求），**pnpm** ≥ 9：`corepack enable pnpm` 或 `npm i -g pnpm`。
2. **Rust 工具链**：rustup（stable），Tauri v2 要求 edition 2021+。
3. **Windows 额外**：
   - Microsoft Visual Studio C++ Build Tools（链接需要）；
   - WebView2 运行时（Win11 自带）；
   - Rust MSVC 工具链（rustup 默认）。
4. 其他平台见 Tauri 官方「平台前置要求」文档（Linux 需要 webkit2gtk 等）。

## 2. 初始化前端骨架

### vite.config.ts

Tauri 场景的三个定制点：固定端口（`devUrl` 依赖它）、不打印清屏（保留 Rust 报错）、
忽略 `src-tauri` 目录监听。

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import { resolve } from "path";

const host = process.env.TAURI_DEV_HOST;

export default defineConfig(async () => ({
  plugins: [react(), tailwindcss()],

  resolve: {
    alias: {
      "@": resolve(__dirname, "src")
    }
  },
  // 1. 防止 Vite 掩盖 rust 错误
  clearScreen: false,
  // 2. tauri 需要固定端口，被占用则直接失败而不是换端口
  server: {
    port: 1420,
    strictPort: true,
    host: host || false,
    hmr: host
      ? { protocol: "ws", host, port: 1421 }
      : undefined,
    // 3. 忽略 src-tauri 的文件变更
    watch: { ignored: ["**/src-tauri/**"] }
  }
}));
```

### src/lib.rs（应用装配骨架）

```rust
pub mod logging;
mod secret;
pub mod terminal;

/// 前端 F12 / Ctrl+Shift+I 打开 DevTools。
/// 浏览器级快捷键被禁用后 F12 不再生效，需要走这个命令手动打开。
#[tauri::command]
fn open_devtools(window: tauri::WebviewWindow) {
    window.open_devtools();
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_shell::init())
        .plugin(tauri_plugin_opener::init())
        // 全局共享状态：所有终端会话表，命令按 session id 定位
        .manage(terminal::Terminals::default())
        // 暴露给前端 invoke() 的命令集合（白名单）
        .invoke_handler(tauri::generate_handler![
            terminal::start,
            terminal::write,
            terminal::resize,
            terminal::close,
            secret::encrypt,
            secret::decrypt,
            open_devtools
        ])
        .setup(|app| {
            logging::init(app);
            // Windows：禁用 WebView2 浏览器级快捷键（Ctrl+F 页面查找栏等），
            // 它们会抢在页面 JS 之前响应，preventDefault 拦不住。
            // 通过 ICoreWebView2Settings3::SetAreBrowserAcceleratorKeysEnabled(false)
            #[cfg(target_os = "windows")]
            { /* webview.controller() -> Settings() -> cast::<...Settings3>() */ }
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

Rust 集成测试放 `src-tauri/tests/`（如 `pty_eof.rs`），`cargo test` 运行。

## 4. 样式体系（Tailwind v4 + HeroUI + SCSS）

三套样式共存，靠 **CSS Layer 优先级** 分层：

1. `src/styles/main.css` —— 只有两行：

```css
@import "tailwindcss";
@import "@heroui/styles";
```

Tailwind v4 与 HeroUI 全部规则都落在 `@layer theme/base/components/utilities`
里（`@heroui/styles` 的 index.css 内部声明了 layer 顺序）。

2. `src/styles/app.scss` —— 项目自定义样式，**无 layer**。
   CSS 规则：未分层的声明永远压过分层的声明，所以 app.scss 里同优先级的
   选择器天然覆盖 Tailwind/HeroUI，不需要 `!important`。

3. 引入顺序（在 `App.tsx`）：

```ts
import "@/styles/app.scss";
import "@/styles/main.css";
```

⚠️ 引入顺序其实不影响结果（分层 vs 未分层才是决定因素），但要保持统一。

### 与 HeroUI 共存的三个已踩坑点（新项目直接预防）

| 坑           | 现象                                                                                                                         | 处理                                                            |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 全局元素规则 | HeroUI 给 `section` 强加 `align-items:flex-start`、给 `header` 强加 `justify-content:space-between`、给 `nav` 加 gap/padding | 自有容器显式还原：`align-items: stretch` 等（见 app.scss 注释） |
| 类名撞车     | 自有 `.tabs` 命中 HeroUI 组件样式 `.tabs{gap:8px}`，标签之间出现缝隙                                                         | 自有规则显式 `gap: 0`；或干脆避开组件库类名（`.tab-list`）      |
| 生成文件     | unplugin 生成的 `auto-imports.d.ts` / `components.d.ts` 被 prettier 改写产生无意义 diff                                      | 列入 `.prettierignore` 与 lint-staged 过滤                      |

### SCSS 项目约定

- 单文件不超 ~1000 行，接近上限按职责拆 partial，在 `app.scss` 里 `@use`。
- 选择器保持两段以内：prettier 会把三段以上选择器强制展开换行，
  与 stylelint 缩进规则无限冲突。

### 5.2 ESLint（eslint.config.js，flat config）

```js
import { defineConfig } from "eslint/config";
import eslint from "@eslint/js";
import tseslint from "typescript-eslint";
import eslintConfigPrettier from "eslint-config-prettier/flat";
import eslintPluginPrettier from "eslint-plugin-prettier";
import reactHooks from "eslint-plugin-react-hooks";
import globals from "globals";

const ignores = [
  "**/node_modules/**",
  "**/dist/**",
  ".*",
  "scripts/**",
  "**/*.d.ts",
  "**/src-tauri/**"
];

export default defineConfig(
  {
    ignores,
    extends: [
      eslint.configs.recommended,
      ...tseslint.configs.recommended,
      eslintConfigPrettier // 必须放最后：关掉与 prettier 冲突的格式规则
    ],
    plugins: {
      prettier: eslintPluginPrettier,
      "react-hooks": reactHooks
    },
    languageOptions: {
      ecmaVersion: "latest",
      sourceType: "module",
      parser: tseslint.parser,
      globals: {
        ...globals.browser,
        ...globals.node
      }
    },
    rules: {
      "no-var": "error",
      ...reactHooks.configs.recommended.rules,
      "@typescript-eslint/no-unused-vars": [
        "error",
        {
          argsIgnorePattern: "^_",
          varsIgnorePattern: "^_",
          caughtErrorsIgnorePattern: "^_"
        }
      ]
    }
  },
  {
    // 配置文件按 Node 环境解析

      "**/*.config.{js,cjs,ts}",
      "**/build/**/*.{js,ts}"
    ],
    languageOptions: {
      globals: { ...globals.node }
    }
  }

```

组合逻辑：`js recommended → typescript-eslint → prettier 关闭冲突格式规则
→ eslint-plugin-prettier 把 prettier 违规升级为 eslint error`。
未使用变量以 `_` 前缀豁免。

# 强制通过 pnpm commit 提交：没有 CZ_GUARD 标记（由 scripts/precommit-check.mjs
# 注入）的直接 git commit 一律拒绝。合并/cherry-pick 产生的提交放行。

git_dir="$(git rev-parse --git-dir)"

   [ -f "$git_dir/CHERRY_PICK_HEAD" ]; then
  exit 0

  echo "❌ 请使用 pnpm commit 提交（需先通过暂存区检查与提交向导）" >&2
  exit 1
fi

### 6.4 lint-staged（.lintstagedrc.js）

核心原则：**按文件类型分组、glob 互斥**，避免同一文件被多个任务并发修改。

```js
export default {
  // JS/TS：拼写 → 格式化 → 规则检查；过滤自动生成的 *.d.ts。
  // 函数型任务不会自动追加文件名，命令里要自己拼。
  "*.{js,ts,cjs,mjs,tsx}": files => {
    const sources = files.filter(
      file => !file.endsWith(".d.ts")
    );
    return sources.length
      ? [
          `cspell lint ${sources.join(" ")}`,
          `prettier --write ${sources.join(" ")}`,
          `eslint ${sources.join(" ")}`
        ]
      : [];
  },

  // 样式不交给 ESLint；Stylelint 在 Prettier 之后修样式规则
  "*.{css,scss}": [
    "cspell lint",
    "prettier --write",
    "stylelint --fix"
  ],

  // 配置/模板/文档只做拼写与格式。
  // cspell 的 ignorePaths 排除了 *.md，暂存 md 时会因"没有文件被实际检查"
  // 退出码 1，故加 --no-must-find-files。
  "*.{json,html,md}": [
    "cspell lint --no-must-find-files",
    "prettier --write"
  ],

  // Rust 不由 Prettier 处理，目前只做拼写检查
  "*.rs": ["cspell lint"]
};
```

### 6.6 自定义 `pnpm commit` 流程（scripts/precommit-check.mjs）

这是本项目最有特色的一环：把「暂存区检查 + 交互式挑选文件 + 提交向导」
串成一条命令，并用环境变量 `CZ_GUARD` 与 commit-msg 钩子配合，
**强制所有提交走这条流水线**。

流程：

```text
pnpm commit
  └─ node scripts/precommit-check.mjs
       ├─ 暂存区为空且工作区无变更 → 报错退出（别填完向导才发现没东西可提交）
       ├─ 有未暂存文件 → 终端多选框（↑↓ 移动 / 空格勾选 / a 全选 / 回车确认）
       │    勾选的文件自动 git add
       └─ spawn git-cz（commitizen 向导，中文提示来自 commitlint.config.js prompt）
            env 注入 CZ_GUARD=1（沿 进程链 传给 git 钩子）
            └─ git commit
                 ├─ pre-commit  → lint-staged（拼写/格式/lint 并回写暂存区）
                 └─ commit-msg  → 校验 CZ_GUARD 存在，否则拒绝
                                  → commitlint 校验信息格式
```

关键实现片段（完整源码见 `scripts/precommit-check.mjs`）：

```js
function launchCommitizen() {
  const child = spawn("git-cz", {
    stdio: "inherit",
    shell: true, // Windows 下解析 node_modules/.bin 里的 .cmd 需要 shell
    env: { ...process.env, CZ_GUARD: "1" } // 钩子据此区分合法提交路径
  });
  child.on("close", code =>
    process.exit(code ?? 0)
  );
}
```

设计要点：

- `CZ_GUARD` 靠进程环境继承传递，**绕过脚本直接 `git commit` 时没有标记**，
  被 commit-msg 拒绝；合并 / cherry-pick 不带该变量但检测到
  `MERGE_HEAD` / `CHERRY_PICK_HEAD` 时放行。
- 交互框用 stdin raw 模式逐键捕获，`finally` 里一定还原终端状态。
- 非 TTY 环境（管道/CI）只提示不阻塞，保证脚本可被自动化调用。

## 8. 经验教训清单（新项目直接规避）

1. **UI 组件库的全局元素规则会污染语义标签**（`section/header/nav`），
   引入后先检查一遍自有布局，显式还原被改掉的属性。
2. **不要与组件库类名重名**（`.tabs`、`.button`、`.dialog`…），
   撞名即继承对方样式；冲突时用无 layer 的自有规则覆盖（未分层 > 分层）。
3. **命令式塞进 React 管辖节点的 DOM（如 xterm 挂载）必须在分支切换时
   用不同 `key` 强制重建节点**，否则残留节点破坏布局。
4. **prettier 与 stylelint 的冲突多因覆盖了继承规则的二级选项**
   （典型：`rule-empty-line-before`），能不覆盖就不覆盖。
5. **lint-staged 各 glob 必须互斥**，函数型任务要自己拼文件名。
6. **cspell 对"没有文件被实际检查"返回退出码 1**，与 ignorePaths 组合时
   记得 `--no-must-find-files`。
7. **pnpm 10 默认屏蔽依赖安装脚本**，esbuild 等需要
   `onlyBuiltDependencies` 显式放行。
8. **Tauri 的 Vite 端口必须 `strictPort`**，否则端口漂移导致
   `devUrl` 白屏且难排查。
